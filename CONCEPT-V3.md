### Почему не BNB (чтобы не возвращаться к вопросу)

- Robinhood Chain за два месяца: $34,6 млрд DEX-объёма, 576 млн транзакций,
  12,3 млн адресов, 190+ токенизированных акций с $3 млрд объёма.
- Главное: дивиденды в акциях требуют, чтобы контракт **автоматически покупал
  акцию на DEX**. Здесь акции нативные и ликвидные. На BNB их фактически нет —
  four.meme пришлось строить ручной кастодиальный 4Stock с минималкой $10 000
  и обработкой до 24 часов. Наша ключевая фича там технически хуже реализуема.
- Риск, который принят осознанно: объём Robinhood Chain падал на 72,5%
  с 11.07 по 01.08; устойчивость сети не доказана.

### Конкуренты

- **Pons** — ~64% комиссий лончпадов сети, $4,54 млрд объёма, $25+ млн заработка создателей.
- **flap** — уже задеплоен на Robinhood Chain (роутер `0x26605f322f7ff986f381bb9a6e3f5dab0beaeb09`).
  Модульный: налоговый токен 1/3/5/10%, произвольная квота, vault-модули.
  Stocks Vault трёх версий: RWAVault (одна акция), IndexVault (корзина + `basketToken`).
  Чужие шаблоны vault разрешены и монетизируются — конкуренты становятся поставщиками.
- **ИИ нет ни у кого.** Ниша пустая. Это единственное реальное поле дифференциации.

## 2. Экономика v3 — ОДИН ВОПРОС ОТКРЫТ

Было: 1% → 50% создателю / 20% команде / 30% казна.

Решения владельца 13.09: **казну убрать**, **команде оставить 20%**.

| Получатель | Доля | Статус |
|---|---|---|
| Создатель токена | 40% | предложение |
| Дивиденды в акциях холдерам | 20% | предложение |
| ИИ-агент токена | 15% | предложение |
| Команда | 20% | **решено** |
| Казна платформы | 0% | **решено** |

**Не хватает 5%** — куда, владелец ещё не сказал. Варианты:
дивидендам (25%, усиливает главную фичу), создателю (45%, переманивает
запуски у Pons), агенту (20%), или оставить комиссию 0,95%.

Ключевое свойство схемы: мёртвый токен перестаёт тратить деньги платформы
сам собой — нет объёма, нет бюджета агента, агент засыпает.

Что уходит вместе с казной: выкупы токенов с рынка и сжигание. История
«hood возвращает народу» теперь держится на дивидендах в акциях —
по сути прямее и честнее, чем косвенная выгода от выкупов.

## 3. Stocks Vault — дивиденды в акциях

### Архитектурный выбор

Деплоить отдельный vault на каждый токен — дорого по газу. Вместо этого
**один общий хаб с учётом по токенам**: `StockVaultHub`.

```
BondingCurvePool (трейд)
   └─ dividendShare ETH ──► StockVaultHub.deposit{value}(token)
                               └─ накапливает ETH по токену

StockVaultHub.harvest(token)   (кто угодно, за вознаграждение от газа)
   └─ swap ETH → выбранная акция через Uniswap V3
   └─ accRewardPerShare[token] += купленное / totalSupply

Холдер: StockVaultHub.claim(token) → получает акцию на кошелёк
```

### Честность распределения

Чтобы «держал — получил, продал — нет» работало без доверия, `LaunchToken`
получает переопределённый `_update`, который при каждом переводе фиксирует
долг пользователя в хабе. Это классический dividend-paying token —
паттерн проверенный, но **повышает газ на каждый трансфер**. Принимается.

Альтернатива (снапшоты + merkle от казначея) отвергнута: требует доверия
к бэкенду, а это противоречит позиционированию «Робин Гуд».

### Открытые вопросы

- **Блокер:** есть ли на Uniswap V3 в сети пулы акция/WETH с реальной
  ликвидностью? Если нет — покупать через USDG двумя хопами. Проверить
  скриптом-зондом до начала работ.
- Одна акция на токен или корзина? Начинаем с одной (v1 flap), корзина потом.
- Минимальный порог harvest, чтобы не жечь газ на копейках.
- Защита свопа от сэндвича: лимит проскальзывания + Chainlink-фид акции
  как санити-чек (фиды у Robinhood Stock Tokens есть).

## 4. ИИ-агент токена

### Он-чейн

`AgentRegistry`: `token => { model, personaHash, budgetWei, owner, enabled }`.
Бюджет пополняется автоматически долей комиссии. Расход списывает бэкенд
подписанной транзакцией; расход публичен и виден на странице токена.

### Офф-чейн

GitHub Pages — статика, агенту нужен бэкенд. **Cloudflare Workers** (Pro уже оплачен):
Cron Triggers для расписания, KV/D1 для состояния, секреты для ключей API моделей.
Firebase Blaze — альтернатива, но Workers дешевле и ближе к уже оплаченному.

Ключи API моделей **никогда** не попадают во фронтенд.

### Что агент умеет в v1

1. Представляется в чате токена при запуске, держит легенду проекта
2. Реагирует на события кривой: крупная покупка, новый ATH, 50% и 90% кривой, градация
3. Постит в X и Telegram по расписанию и по событиям
4. Отвечает на вопросы о проекте в чате токена

### Границы (обязательно)

Агент не даёт финансовых советов, не обещает доходность, не призывает покупать.
Закладывается в системный промпт **и** в Legal.jsx. Это не формальность:
автономный бот, обещающий прибыль от имени платформы — прямой юридический риск.

## 5. Конструктор автоматизации

Второй слой поверх агента: создатель собирает правила «событие → действие»
без кода. `при градации → пост в X`, `кит купил >1 ETH → объявить в Telegram`,
`каждые 6 часов → отчёт по объёму`. Ответ на модульность flap, но про жизнь
проекта, а не про токеномику.

Делается **после** того, как агент v1 работает. Не раньше.
