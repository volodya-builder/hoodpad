## ⚠ В МЕЙННЕТЕ СБОРКА СТАРШЕ РЕПОЗИТОРИЯ (проверено 14.09.2026)

Фабрика `0x08a8…23ec` в сети **не соответствует** `contracts/LaunchpadFactoryV2.sol`. Проверено чтением развёрнутого байткода: селекторов `proposeConfig` / `applyConfig` / `pendingConfig` / `CONFIG_DELAY` там нет, есть `setConfig(address,address,address,uint16,uint16)` — мгновенный, без таймлока.

Значит развёрнута сборка **до коммита `ba18f5c5`** («hardening batch»), и на мейннете отсутствует всё, что тот коммит добавил:

- мигратор по-прежнему тратит ETH на выравнивание цены — **та самая уязвимость** (мог выкупить мешок атакующего за 6.5 ETH);
- нет проверки, что вызывающий — зарегистрированный пул;
- лимит закупки создателем обходится (он не перенесён в пул);
- нет лимитов на метаданные;
- нет таймлока конфига.

**Правило: состояние мейннета проверять по байткоду и `eth_call`, а не по исходнику в репозитории.** Они разошлись.

## Мастерская и журнал агента (13.09.2026)

Вкладка «Мастерская» (`web/src/pages/AI.jsx`) — всё про ИИ-агентов монет. Три живых блока:

- **Голосование** (`lib/workshop.js`, `components/Workshop.jsx`) — недельные раунды, считаются из времени, без сервера. Пн–Ср предлагают (порог 1M токенов), Чт–Вс голосуют, вес = баланс.
- **Очередь** (`components/Queue.jsx`) — победители закрытых раундов по всем монетам.
- **Журнал** (`lib/journal.js`, `components/Journal.jsx`) — задание, план, ссылка на результат, расход на модели. Провалы показываются наравне с удачами, с причиной.

**Firebase открыт на запись**, поэтому подделать можно любую строку. Защита одна и та же везде: подписывать кошельком и проверять подпись при чтении; несошедшееся выбрасывать и показывать число выброшенных. Сообщение для подписи считается из содержимого — правка суммы или ссылки в готовой записи ломает подпись.

**Ключ оператора журнала** — отдельный, не командный, денег не держит, умеет только подписывать записи. Создаётся `node scripts/journal-operator.mjs --newkey`, кладётся в `JOURNAL_OPERATOR_KEY` на машине владельца, адрес — в `VITE_AGENT_OPERATOR` (по умолчанию = кошелёк команды). Утечка = фальшивые записи в журнале и ничего больше; лечится сменой адреса в конфиге. Командный ключ сюда класть нельзя.

`scripts/journal-operator.mjs` заводит записи из победителей раундов. **По умолчанию сухой прогон**, пишет только с `--write` — в проекте уже был бот, автоматически делавший «полезное» и сжёгший ~$70.

Оплата моделей: практический путь — OpenRouter (USDC, +5% за крипту, автопополнение по порогу, API баланса, 500+ моделей). Полностью автономный x402 отпадает — там три модели и нет GPT/Claude. Разрыв «ETH на Robinhood Chain → USDC на Base» закрывается вручную раз в неделю: автоматизировать его = отдать боту ключ от кошелька.

Позиционирование (см. AI-AGENT.md): обещаем **действие, а не результат**. «Первый ИИ-лончпад» — неправда (Virtuals), «агент строит вам бизнес» — не подтверждено (известный месячный опыт с живым бюджетом дал $0).

## Выбор модели ИИ при запуске монеты (14.09.2026)

Во вкладке «Создать» создатель выбирает модель, на которой будет работать ИИ его монеты. Выбор уезжает в метадату токена (`ai` = id модели, `aiName` = человеческое имя) тем же data-URI, что и картинка, — то есть **в контракт, навсегда**.

**Список живой, вбивать его руками нельзя.** Первая версия была списком из 14 моделей, набранных по памяти; сверка с каталогом OpenRouter показала, что на тот день не существовало **ни одной** из них — версии сменились. Вбитый список протухает молча, и человек узнаёт об этом, когда его монета не собралась. `web/src/lib/models.mjs` читает `https://openrouter.ai/api/v1/models` (ключ не нужен, CORS открыт) и отбирает годные.

Правила отбора (`usable`): текст на выходе, не `:batch`-копия и не алиас `~`, не роутер `openrouter/*`, цена **до $20 за миллион** выходных токенов, есть рейтинг. Потолок цены обязателен: модель выбирает создатель монеты, а платит платформа. Без него в списке оказывается `openai/o1-pro` за $600 за миллион.

Сортировка — по рейтингу `benchmarks.design_arena`, категория **website**: агент делает ровно веб-страницу. «Самая дорогая» и «самая новая» обе дают мусор (у OpenAI дороже всех старая o1-pro, у Meta новее всех Llama Guard — классификатор).

В форме до поиска — по одной лучшей модели от каждого разработчика; поиском достаётся весь список. Каталог не ответил — **выбор не показываем вовсе**: лучше без выбора, чем выбор из вранья.

Руками в `MAKERS` записаны только приставки разработчиков (`anthropic`, `openai`, …) — они живут годами, в отличие от имён моделей. Оттуда же берутся значки (фавиконки с сайтов разработчиков, как логотипы акций с CDN).

**Агент выбирает по тому же файлу.** `scripts/agent-run.mjs` импортирует `loadModels` из `../web/src/lib/models.mjs` — расхождению «форма обещает, агент не умеет» взяться неоткуда. Расширение `.mjs` не для красоты: в `web/` нет `"type": "module"`, обычный `.js` агент прочитать бы не смог.

Если выбранной модели в списке нет (сняли с обслуживания или вылетела за потолок цены) — агент строит на лучшей доступной и пишет в отчёт поле `asked`; журнал показывает «просили такую-то». **Молча подменять нельзя**: тогда на витрине не отчёт, а реклама. Каталог недоступен целиком — агент останавливается, а не строит наугад.

Проверить список, ничего не потратив: workflow «Агент строит» → Run workflow → mode `models`.

## Как выкатывать (порядок, 14.09.2026)

**Локальный репозиторий всегда стоит на `staging`. Ветку не переключать.** Переключение ломается заначками GitHub Desktop и файлами-блокировками в `.git`, которые из песочницы Claude не удаляются (`Operation not permitted` даже после выдачи прав на удаление). Каждая git-команда Claude оставляет за собой `.git/index.lock`, который блокирует следующую операцию GitHub Desktop — Claude обязан сметать локи в конце каждого вызова.

Порядок:

1. Claude коммитит в `staging` (ветка уже выбрана — переключать нечего).
2. Владелец жмёт **Push origin**.
3. Проверяет **hoodandarrow.com/staging/** (жёсткое обновление Ctrl+F5 — Cloudflare кэширует).
4. Если нормально — на **github.com** кнопка **Compare & pull request** (staging → main) → **Create** → **Merge pull request**.
5. Дальше `deploy.yml` сам пересобирает боевой сайт.

Шаг 4 делается в браузере именно потому, что локально переключать ветки нельзя. Заодно видно дифф: что конкретно поедет в бой.

**Кнопку выката одним нажатием сделать нельзя:** файлы в `.github/workflows/` защищены от записи удалёнными инструментами. Если владелец захочет — он может создать `promote.yml` сам через веб-интерфейс GitHub.

## Правила работы (для Claude)

1. Отвечать по-русски. Работать автономно, не дёргать по мелочам.
2. Деплой сайта = коммит + пуш. Пуш делает владелец кнопкой Push origin в GitHub Desktop (git в песочнице не авторизован — это нормально, не чинить). Коммитить с `-c user.name -c user.email`, при залипших `.git/*.lock` — удалить и повторить.
   **Из песочницы Claude файлы внутри `.git` удалить нельзя** (`rm` → Operation not permitted),
   поэтому лок не удаляют, а переименовывают, и проверять надо и `index.lock`, и `HEAD.lock`:
   `for f in .git/index.lock .git/HEAD.lock; do [ -e "$f" ] && mv "$f" "$f.old"; done`
   Git создаёт лок на каждую операцию и не может его убрать за собой, поэтому
   блокируется СЛЕДУЮЩАЯ команда — сдвигать локи надо перед каждым `commit`.
2б. **Перед КАЖДЫМ коммитом смотреть `git diff --cached --stat`.** 13.09.2026
   рабочее дерево в папке внезапно откатилось к старому состоянию, один из
   ранних `git add` затащил этот откат в индекс, и следующий коммит (4192dbab)
   тихо стёр фичефлаги шапки, CONCEPT-V3.md и зонд пулов — хотя добавлялись
   только два файла контрактов. Индекс переживает неудавшиеся из-за локов
   коммиты и накапливает в себе лишнее. Добавлять только явными путями,
   и глазами сверять список файлов перед `git commit`.
2а. **Все изменения сайта сначала в ветку `staging`** (тестовый сайт hoodandarrow.com/staging/, деплой из `deploy-staging.yml` в подпапку gh-pages/staging, база `/staging/`, плашка STAGING, закрыт от индексации). В `main` (боевой сайт) — только merge из staging после одобрения владельцем. Напрямую в `main` — только инфраструктура/докуметация по согласованию.
3. **Никогда** не запрашивать приватные ключи/сид-фразы. Деплой контрактов владелец делает сам локально (`scripts/deploy-mainnet.js`, deploy-kit).
4. Не трогать `.github/workflows/mirror.yml`.
